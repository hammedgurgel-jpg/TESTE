Domain docs

Layout: single-context.

CONTEXT.md at the repo root holds the domain model: core terms, entities, and how they relate.
docs/adr/ at the repo root holds Architecture Decision Records — one file per decision, numbered sequentially.
Consumer rules
Before making a structural or terminology decision, read CONTEXT.md first.
When a decision changes the domain model or reverses a prior ADR, update CONTEXT.md and add a new ADR — don't silently edit old ADRs.
Keep CONTEXT.md current: it should reflect the system as it is now, not a history log (that's what ADRs are for).
